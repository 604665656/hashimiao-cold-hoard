# 开发日记 · 极寒末世囤货模拟器

> 单文件离线 AVG。`极寒末世囤货模拟器_完整版.html` 一页拷走就能玩，不联网、无外链。
> 配套：美术生图排期.md / 体积校验报告.md / 开发日记_体积闸门与分享机制.md（专项附录）。

## 一、要解决什么

1. 把「极寒末世倒计时 + 天气恶劣度 + 可支配资金」做成能真玩的 AVG：设定 → 采购（钱与工时双限）→ 封门逐日消耗 → 突发事件二选一 → 结算天数 / 死因 / 评级。
2. 结局不能只有一个分数。天气、资金、行为各成一轴，11 个结局按优先级判定，且开局就把差异预告给玩家。
3. 排版要有设计感、流程要够长、要有排行榜和分享，且**全部塞进一个 HTML**——单文件最容易悄悄变大，必须带构建闸门。
4. 美术用哈士喵的现成资产 + 按统一锚点补图，分轮排期做完，每轮报剩余轮次并顺手查 bug。

## 二、怎么做的

**玩法**
三幕结构（初冬 / 深冬 / 白毛风季），每 7 天一次营地会议；25 个事件含 5 条跨天连锁；天气带专属事件池与禁用表，资金档解锁赊账 / 被盯上 / 钱没花完；`karma` 分出结盟线与独狼线。`resolveEnding(ctx)` 纯函数按优先级 `find()`，特殊结局排在天数兜底前面。

**系统**
结局图鉴（11 格，未解锁不剧透）、开局分支预告、断点续玩（逐日存档含随机序列）、本机榜 + 好友榜、`HSM1-` 成绩码带 djb2 校验位、Canvas 生成 750×1000 PNG 分享卡。

**美术分轮**（详见 `美术生图排期.md`）
- R1 9 张事件卡插画，替换 archive 网页截图
- R2 3 张幕间插画（16:9 偏右裁 9:16），三幕各一张底图
- R3 4 张真实角色差分，绿幕泛洪去背成立绘六态；CSS 滤镜伪状态全部退场
- R4 物资卡专图 ✅ 完成（最后一轮）

**门缝交易 / 留钱念想（R4 一起补的）**
原本「钱」只在采购期作限时预算，封门后就是死数，玩家过程中既不能买也不能卖 —— 这确实少了半条命。补了 `🪙 门缝交易`：封门后每天可开一次，7 种物资都能买 / 卖，买价随天数与天气涨（白毛风 ×2.10 且每天只递 2 件），卖出四折；买到的功能件并入事件与结局判定。另外花 ¥88 可留一封没寄出的信，结算页「账本最后一页」按余额分档给一句人话，分享文案与成绩卡都带余额；`END_MONEY` 判定不动，结语改成把钞票夹回账本。

**v1.0 发布收尾（第五批次，冻结功能）**
这轮**不加玩法**，只把项目收成可上架、可复核、可追溯的稳定版：
- 页脚注入 `v__BUILD__` 版本标记，构建脚本写 `release_meta.json`（版本 / 构建号 / 时间），闸门同步新增「占位符已全部注入」对 `__BUILD__` 的识别和「发布版本标记已写入」检查项 —— 硬校验从 11 项变 **12 项**。
- `make_release.py` 用**显式白名单**组装上架包：主产物 + 上架说明 / 发布说明 / 版权声明 / 看板待办 / 验收日志 / 体积历史 / 五份工程文档 / 五个构建校验脚本 / 三屏预览 / `发布清单.json` / `SHA256SUMS`，共 21 个条目。打包后读回 zip 逐文件比对 sha256。
- 包内 `tools/browser_check.js` 单独生成**适配版**：绝对路径改相对包根、截图输出到 `_shots/`、Chrome 路径走 `CHROME_PATH` 环境变量；工作区原件不动，回归照常跑。
- 上架包里**不重建 HTML 所需的素材目录**，只附构建后的产物与校验结果；版权声明写明授权边界与未随包分发的内容。

**为什么冻结**：产物 597.9 / 600 KiB 只剩 2.1 KiB，P1-3 原估 2–5 KiB，硬塞会顶闸门；而改数值会冲掉已验证的 11 结局可达性与 7→11 天交易对照。剩余 7 条按 P0 / P1 / P2 三档写进 `看板_待办.md`，留给下一版。

**P1-1 每日挑战 / 种子（第四次批次）**
主页新增一行「🎯 今日挑战 / 📥 挑战码」。`todaySeed()` 由本地日期算 FNV 哈希，`chalCode(seed)` 出 `HSMS1-<base36>-<校验位>`，`parseChal()` 验校验位；`chalCfg(seed)` 派生天气 / 2–5 天 / 四档资金。
**核心改动在 `sealDoor()` 的 `setSeed()`**：挑战局锁 `chal.seed`，普通局维持原算法。于是同种子 = 同天气、同预算、同事件序列；玩家采购不同才分高低，这正是挑战可比的地方。
成绩码加 `s` 字段并纳入 `codeSum` 签名，排行榜显示 `🎯#种子`；`hsm_last` / 分享文案 / 成绩卡都带挑战码。手改倒计时 / 资金 / 天气即 `chal=null` 退出挑战（诚实，不假装还是同一局）。存档与续玩都带 `chal`。
按 README 规矩没建服务端：挑战码是离线字符串，防手滑不防作弊，官方实时榜仍需后端，不在本项目范围内。

**P1-2 事件权重治理（同批次）**
`pickEvent()` 在原有「天气/幕专属 ×1.8、连锁/幕事件 ×1.45」之上叠两层：3 天内出现过的事件按 `gap` 降权（最多 ÷3.7）；连续 `dry>=4` 天没抽到事件时，关键事件（专属 / 连锁 / 幕事件）权重按 `1+.35*(dry-3)` 上升，封顶 ×2.5。`st.eventLast` 记上次出现日、`st.dry/maxDry` 记空窗；抽中清零、空日累加，续玩兼容旧存档。分支统计新增「最长空窗 N 天」。
**刻意不写死「第 X 天必出」**：软保底只削极端坏局，不消除风险，也不让玩家背板。

**生产构建减法（第三次批次，先腾体积）**
产物 597.1 KiB 只剩 2.9 KiB，P0-5 教学按调研估算要 2–4 KiB，硬塞会顶闸门。按 README 那套「单文件最容易悄悄变大」的规矩，新建 `shrink.py`：模板保持可读，只在写产物前做**语义等价**压缩 —— 删 HTML 注释 / 独立单行块注释 / 行首缩进 / 标签间换行缩进 / CSS 换行 / 连续空行，共 6 步，**净省 3.2 KiB**（597.1 → 593.9，余量回到 6.1 KiB）。
关键约束：每一步都过 `check_invariants()`，比对**全部 37 张图的 base64 内容 sha1 指纹**、script 段数、静态 DOM id 指纹、style 段数；任何一项变化直接抛异常中止构建。账单写进 `减法账单.md`，六步各记节省字节。反证过：改 1 个 base64 字符 / 改 1 个静态 id / 删 1 个 `<script>` 全部被拒。

**P0-5 首局引导（同批次）**
`let tut` 由 `hsm_tutorial_v1` 判定；首次进入走引导：开场换成两行说明，选项多一个「跳过引导，按老规矩来」；`setup()` 预设冷冬 / 3 天 / ¥1500，设定页提示行标「首局固定，下局全开放」；采购页给 `quickKit` 加 👉 并把台词压成一次决策（先保身体再补粮水煤）；封门提醒「余额还能从门缝交易递东西」；结算写完成标记 + 解锁说明。重开后三项设定全归玩家。
**简化如实记**：固定档是「预设 + 仍允许手改」，没硬锁控件；也没做「3 次独立决策」，而是用已有的预测条和推荐按钮把 7 次同构选择收成 1 次。引导不碰任何数值、不碰 11 结局判定。

**P0-2 最后窗口（第二次优化批次）**
当粮/水/煤按当前速率只剩 ≤2 天时，在 `consume()` 扣完当天消耗之后、进下一天之前，弹一次性的「⚠ 最后窗口」：惊恐态立绘 + 欠条红印卡面 + 三个都得付代价的选项 ——
「最后一次递取」按门缝价补 2 天份（钱不够就少补并多扣健康，统一 −5 健康）、「收紧到极限」`rations=1` 让此后每天少耗 1 份粮/1 瓶水（−10 健康）、「不折腾，把账合上」接受结局。
`st.grace` 一局只写一次；`graceInfo()` 只判物资断供，不判慢性失温 —— 没睡袋是开局决策的后果，不该在最后白送一次翻盘。窗口不进 `st.eventIds`，不污染事件统计；快进不走 `consume()`，复盘会写「快进推演，未逐日触发」。复盘新增「最后窗口」证据行（补救 / 合上账本 / 快进 / 未逼近四种口径），同步进 `hsm_last.grace`、分享文案和分支统计。

**P0 优化批次（同类调研落地，生图排期归零后的第一次）**
对照《同类生存囤货游戏调研与优化建议.md》的第一周顺序做了三条：
- **P0-4 体积门禁 → 资源账单**：`check_size.py` 加 590 KiB 预警线、逐张解码 37 张内嵌图（格式 / 原始尺寸 / 解码字节 / base64 字符）写成账单表、去掉 data URI 后的「文案/代码字符数」与上次差值。纯构建期，产物零增量。
- **P0-1 结局关键证据**：`st.trace` 逐日记 `[天,粮,水,煤,体]`，新增纯函数 `summarize(ctx,st)` 输出首个失衡日、断供前 3 天轨迹、天气燃料倍率、交易与善缘，以及一条按死因分派的「下次改一处」。接进结算页复盘块、分享文案和 750×1000 成绩卡。
- **P0-3 采购期预测**：按当前天气 + 初冬口径算粮/水/煤/身体预计天数并标出最短板，换天气立刻重算。预测只给下限、不含随机事件，不泄露后续。
顺手把门缝交易的「每天 2 件」口径写精确为「每天 2 次递取，买或卖各算 1 次」。

**构建闸门**
`build_game.py` 注入素材 → `check_size.py` 硬校验：总产物 ≤ 600 KiB、无外链、占位符全注入、11 张结局插画 / 3 张幕间 / 4 张差分齐全、差分带 alpha、JS 语法；分项拆账七项严格加总，12% 增长护栏写入 `size_history.json`。超硬闸门直接 `exit 1` 中止构建。

## 四、坑

1. **HUD 重写冲掉 DOM 节点**：`tickShop()` 每次刷新预算都重写 `hud.innerHTML`，把 `<b id="hudDex">` 一起冲掉，导致 `endGame()` 中途抛 `TypeError`，结算页的分支统计 / 日志 / 分享文案全被吞成空白。浏览器里连报 3 次才定位到。修法：刷新时把节点一起写回，且 `homeInit` / `endGame` 取值处加空值保护。
2. **分项拆账别单列「结构开销」**：初版把「去掉所有 data URI 后的字节」和 `total − skeleton − inline` 并列，后者恒为 0，等于同一块算两次。改成「其余 = total − 各项素材」才严格自洽。
3. **node 校验不能塞命令行**：内嵌脚本近 400 KiB，`node -e` 传参会 `Argument list too long`；落临时文件让 node 读，验完即删。
4. **成绩码去 padding 要补回来**：为紧凑去掉尾部 `=`，`atob` 前必须 `while(s.length%4) s+='='`，否则中文昵称解码失败。校验位只防手滑，不是签名——防刷榜要服务端，那就不是单文件了。
5. **存档时序**：幕卡 / 会议的去重标记在 `saveRun()` 之后才写，停在幕间卡刷新会重复弹过场。标记必须**先写、立刻存**。
